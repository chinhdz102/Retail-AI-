# Flow 1–5 live test — 2026-11-18

## Test setup

The submitted 30 turns were run as five independent sessions against the active snapshot catalog. Each flow kept one session across its six turns. Raw responses are in [`flow_1_5_snapshot_live_20261118.json`](flow_1_5_snapshot_live_20261118.json).

| 1. Milk search and advice | 6/6 | 6.49 s | 33.88 s | Product retrieval worked. Multi-turn filtering and transaction handoff had gaps. |

## Flow 1

- The first turn found three verified milk products.
- The initial live run treated “loại nào ít đường hoặc không đường?” as an unsupported nutrition question. This was corrected so label filters are treated as product constraints while factual nutrition questions still abstain.
- “Loại nào có giá rẻ nhất?” initially lost the previous candidate set. The follow-up price-extrema route now selects the minimum from the remembered product IDs. A recheck returned Cô gái Hà Lan không đường 180ml at 6.000đ.
- Nutritional comparison correctly abstains because the catalog has no verified nutrition fields.
- The latest recommendation for a customer limiting sugar selected the verified “không đường” product.
- “Lấy cho tôi 2 hộp loại vừa đề xuất” is now recognized as a reference purchase with quantity 2. Snapshot mode still refuses to create a transaction cart.

## Flow 2

All six requests returned HTTP 200, but the chain does not yet meet the intended semantic quality.

- “Ăn sáng nhanh, không cần nấu” returned Bánh cốm, Dorayaki and a snack. The result mixed categories and included a large 310g product without a verified no-cook or filling claim.
- The follow-up “vừa rẻ vừa đủ no” failed closed without preserving the candidate set.
- “Không muốn ăn bánh mì” produced free-form alternatives without grounded product IDs.
- Protein comparison correctly abstained because protein data is absent.
- Stock/substitute and 50.000đ meal planning failed closed instead of returning a grounded substitute or a constrained basket.

## Flow 3

Snapshot mode is intentionally read-only for cart writes. The submitted flow therefore did not create a cart. The current demo profile was also checked separately in [`flow_3_demo_current_20261118.json`](flow_3_demo_current_20261118.json).

- The requested demo milk SKU `MILK01` is expired in the current demo fixture, so the atomic multi-item add kept the cart empty instead of partially adding water and noodles.
- The positive control using `WATER01` and `NOODLE01` passed. Add 3 water plus 2 noodles produced 55.000đ, updating noodles to 5 produced 106.000đ, and removing noodles left 21.000đ.
- Cart total phrases now route to the cart controller.
- “Trong giỏ hàng có sản phẩm nào đang được giảm giá?” now scopes promotion lookup to the current cart. Snapshot mode reports that a transaction cart cannot be verified.
- Free-shipping thresholds are not present in the repository, so the assistant must abstain on the threshold and amount remaining.

## Flow 4

The six turns returned HTTP 200, but the result is not a valid constrained basket.

- The first budget statement did not create a concrete basket plan.
- The diet correction and fruit-juice addition were handled by fallback paths. One response suggested 71.800đ fruit juice without proving that the total remained below 200.000đ.
- The final list and remaining budget could not be calculated from a stable cart or plan state.

## Flow 5

The catalog does not contain order history, revenue, daily sales counts, stock velocity, or replenishment records. The latest guard now returns the same explicit local-policy response for all six management questions:

> Mình chưa có dữ liệu đơn hàng, doanh thu, tốc độ bán hoặc nhập hàng đã xác minh của cửa hàng này.

The original live run predates that guard. Turn 29 received HTTP 502 because all provider attempts were rate-limited. This is recorded in the raw JSON and was not converted into a fabricated business answer.

## Changes made during this test

- Added generic label-filter handling for “ít đường/không đường”.
- Added context-aware minimum/maximum price follow-ups.
- Added quantity-aware references such as “2 hộp loại vừa đề xuất”.
- Added multi-product purchase parsing for “muốn mua 3 chai…, 2 gói…”.
- Added cart-scoped promotion lookup.
- Added explicit fail-closed handling for store sales and replenishment analytics.

Targeted tests passed after these changes. The full demo-profile suite passed **1,107 tests**. Snapshot-specific tests that expect demo-only IDs such as `COKE_ZERO_330` must be run with `CATALOG_REPOSITORY=demo`.
