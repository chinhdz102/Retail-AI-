# Consultation simplification and offline replay — 2026-11-04

The five-call architecture loses useful advice through repeated free-form generation, not only retrieval. Planning guidance invents product properties and is repeated as authority in selection/review. Selection generates prose containing prices that the server can inject exactly. Review evaluates drafts and revisions inconsistently, then a second full selector changes choices and repeats mistakes. Several failures are structural (question metadata, numeric formatting), yet trigger expensive semantic regeneration.

An incremental minimum change is to preserve plan/selection/review but change repair routing: when all selected items fit the purpose, retain picks/quantities and pass only selected facts, canonical draft, exact local validation issue and customer constraints to a compact editor. Independently check its final claims and re-render deterministically. Replan only when physical function is wrong. A negative review's revised text must not automatically be accepted: the captured v2 revision invents tenderness and still fails the renderer. The final hotpot revision renders but remains unacceptable under its captured reviewer; this is evidence of review convergence failure, not proof it is safe to publish.

For deeper simplification, planning should emit retrieval intent and constraints only, without a prose guidance draft. The answer stage should choose a preferred item and facts-based rationale, with names/prices bound by the server. A risk-aware evidence check can focus on readiness, clinical/chemical use, compatibility and unsupported effects. Retain independent semantic checking until offline and live cases demonstrate that reduced checks preserve grounding. Do not replace errors with canned advice or loosen price/claim validation globally.

Retrieval should prioritize diverse observable physical forms relevant to the purpose. The hotpot final shortlist included processed pork and minced imported beef; models turned mince into slices. Ordinary whole meat should remain eligible for customer slicing, and type-specific preparation must be conditional rather than invented SKU readiness. Known-purpose empty searches should trigger bounded category discovery rather than losing products through an advice-only shortcut.

Offline helper `evaluation/replay_captured_consultation.py` replays captured selections and reviewer revisions against the current renderer and review publication gate. It reconstructs catalog facts from the original context and performs no network calls. `artifacts/offline_captured_draft_replay_20261104.json` records three traces. Current code accepts the revised cereal preparation that previously failed the broad phrase guard; it still rejects invented prices, unsupported tenderness and question metadata defects. Renderer acceptance is explicitly not a usefulness rating.

## Lean selection wire contract

The captured `hotpot_vn_policy_direct_20261103_a.json` had a genuinely sliced 200g beef candidate at index 2 (87,100đ), while index 0 was explicitly minced (68,700đ). Both generated selections chose these two. The first was rejected before semantic review because it unnecessarily emitted `basis=label` with null `label_quote`, although the task had no sugar-label claim. The later selection still described minced beef as equally appropriate and added unsupported taste/preparation assertions. Removing bookkeeping cannot solve those semantic defects, but prevents a redundant field from wasting the repair attempt.

`_tool_schema(GroundedSelection)` now removes `basis` and `label_quote` from pick properties and required lists in strict native JSON and legacy tool schemas. Purchase identity, quantity and task role remain. Local `GroundedPick` retains its declared category/empty-string defaults and legacy label validation; actual customer sugar filters and catalog grounding are untouched. Unknown extra fields still fail local validation. The model's policy must request only fields present in the wire contract. Regression coverage includes strict/tool schemas, lean tool output default restoration/rendering, native unknown-field rejection and retained unsupported-label rejection.
