\chapter{Methodology}

This chapter presents the scientific design of the Dual-Agent AI system around four core elements: AS-IS versus TO-BE process analysis, the functional AI architecture and cross-agent \code{crosswalk.csv}--API bridge, our two primary algorithmic designs (\emph{Zero-Planner Hybrid Routing} and \emph{Profit-Gated Router \texttt{B-Gate}}), and complete training and hyperparameter selection specifications. Software engineering details (UI stack, deployment containers, file paths, and supporting client-side speech engineering) are placed in Appendices~A--C.

\section{Business Process Analysis}

In a Vietnamese supermarket managing 3,000+ dry/ambient SKUs alongside 150--300 daily-replenished fresh SKUs, two manual loops (AS-IS) jointly degrade service quality and operating margin: (i)~shoppers manually hunt for pack-size unit value or wait for associates during peak hours; and (ii)~store managers guess fresh orders from right-censored POS logs and apply late flat 30\% evening markdowns. Figure~\ref{fig:as_is_to_be} contrasts this manual baseline with our coordinated dual-agent workflow (TO-BE), where AI handles perception, mathematical optimization, and grounded option generation while humans retain final execution control.

\subsection*{Inter-Agent Data Exchange Mechanism (\code{backend/services/ops_bridge.py})}
To unify both agents without weakening HITL isolation, we implemented a three-part read-only fail-closed bridge:
\begin{enumerate}
    \item \textbf{Bi-directional Crosswalk (\code{OpsCrosswalkIndex}):} Loads \code{data/bridge/crosswalk.csv} mapping all 164 \texttt{ops\_chest} fresh SKUs (\code{F0004}--\code{F0793}) to 164 valid \texttt{Retail-AI-} \code{product_id} entries.
    \item \textbf{HITL-Guarded Read-Only Client (\code{OpsChestBridgeClient}):} Polls \code{GET /api/inventory/summary}, \code{/api/inventory/items}, and \code{/api/inventory/expiring} under a bounded freshness window (\code{freshness_ttl_seconds = 300}). Only markdown proposals in \texttt{APPROVED} or \texttt{EXECUTED} state are accepted; \texttt{PENDING} and \texttt{REJECTED} proposals are discarded.
    \item \textbf{Catalog Overlay Decorator (\code{BridgedProductRepository}):} Overlays fresh live stock (\code{stock_is_current=True}) and approved FEFO markdown prices onto \code{ProductSnapshot}. When \code{on_hand == 0}, in-stock searches (\code{in_stock=True}) and promotion feeds suppress the out-of-stock SKU to surface available substitutes, whereas direct SKU inquiries honestly report zero sellable units. Whenever \texttt{ops\_chest} is stale ($>300$\,s) or returns HTTP~503, the decorator fails closed to the verified static catalog snapshot (\code{stock_is_current=False}).
\end{enumerate}

\section{Contribution 1: Zero-Planner Hybrid Routing (\texttt{Retail-AI-})}

Conventional multi-step LLM agent loops execute 2--4 sequential calls (planner $\to$ selector $\to$ reviewer) on every turn, inflating latency to 5--14\,s and risking price drift. Algorithm~\ref{alg:zero_planner_sse} formalizes our \textbf{Zero-Planner Hybrid Routing} pipeline across four clear tiers ordered from fastest to strictest:
\begin{itemize}
    \item \textbf{Tier 1 -- Sub-3\,ms Deterministic Safety \& Smalltalk Gates:} Instantly blocks medical/medication advice, OWASP prompt-injection attempts, and out-of-catalog items with zero LLM calls.
    \item \textbf{Tier 2 -- Deterministic Catalog Tools (0 LLM calls):} Directly resolves single-SKU price lookup, 13-aisle shelf locations, verified product knowledge attributes, synchronized 30-day bestsellers (\code{data/synced_sales_30d.json}), snapshot/bridge stock checks, and Turn-1 semantic cache hits (Jaccard $\ge 0.88$, always bypassing medical/allergen queries).
    \item \textbf{Tier 3 -- Zero-Planner Grounded SSE Streaming \& 1-Call Baskets:} For browsing, unit-price comparisons (Eq.~\ref{eq:unit_price}), promotions, and budget meal baskets ($\sum P(p) \le B$), catalog retrieval finishes first and emits verified product cards immediately, followed by a \textbf{single} streaming LLM pass locked to those SKUs.
    \item \textbf{Tier 4 -- Bounded Structured Planner:} Reserved strictly for complex multi-condition allergen or unresolved multi-constraint queries.
\end{itemize}

\intuitionbox{Step-by-Step Walkthrough: How a Shopper Query Flows Through Zero-Planner}{%
When a shopper asks \emph{``Cho mình xem sữa tươi không đường''} (Show me unsweetened fresh milk): (1)~\textbf{Tier 1} clears medical/OWASP checks in $<3$\,ms; (2)~\textbf{Tier 3} queries the inverted index across 3,081 Thanh Lam Mart SKUs and streams verified product cards to the screen in \textbf{242\,ms}; (3)~a \textbf{single} streaming LLM pass summarizes the top pick, finishing end-to-end in \textbf{617\,ms} on live production---$11\times$ faster than the 6.85\,s multi-call planner baseline.}

\begin{algorithm}[htbp]
\caption{Zero-Planner Hybrid Routing with Grounded Tools (\texttt{Retail-AI-})}
\label{alg:zero_planner_sse}
\footnotesize
\begin{algorithmic}[1]
\Require User query $u$, session context $S$, bridged catalog $\mathcal{C}_{\text{bridge}}$, synchronized sales store $\mathcal{D}_{\text{sales}}$
\Ensure Grounded Vietnamese/EN response with verified product cards $K$ and provenance metadata
\State Normalize $u$ (catalog-anchored brand repair); evaluate sub-3\,ms deterministic gates (medical/drug refusal, OOC, OWASP injection, social smalltalk)
\If{deterministic gate triggers}
    \State Return immediate deterministic response (0 LLM calls); \Return
\EndIf
\If{non-clinical Turn-1 \textbf{and} semantic cache hits (exact $O(1)$ or Jaccard $\ge 0.88$ with matching constraint signature)}
    \State Deep-copy session memory $S'$ and return cached reply (0 LLM tokens); \Return
\EndIf
\If{$u$ is a single-SKU lookup, shelf location, verified label query, 30-day bestseller, or stock ranking query}
    \State Execute deterministic tool on $\mathcal{C}_{\text{bridge}}$ or $\mathcal{D}_{\text{sales}}$; attach explicit provenance metadata
    \State Return deterministic grounded reply (0 LLM calls) with cards $K$; \Return
\EndIf
\If{$u$ requests a budget-capped meal/combo basket ($\le B$)}
    \State Retrieve template slot candidates from $\mathcal{C}_{\text{bridge}}$ (suppressing live OOS SKUs) and select $K_{\text{basket}}$ satisfying $\sum_{p \in K_{\text{basket}}} P(p) \le B$
    \State Emit cards $K_{\text{basket}}$ immediately; stream concise explanation via \textbf{1 LLM call}
\ElsIf{$u$ is a standard browse, unit-price comparison, promo, or exclusion query}
    \State Execute inverted-index search + exclusion filter + unit-price ranking (Eq.~\ref{eq:unit_price}) to obtain top-$k$ cards $K$
    \State Emit cards $K$ prior to token streaming; stream grounded explanation over locked $K$; store Turn-1 cache entry
\Else
    \State Escalate complex allergy/clinical or unresolved multi-constraint queries to bounded structured planner
\EndIf
\State Persist updated session state $S'$ and return
\end{algorithmic}
\end{algorithm}

\subsection*{Supporting Multimodal Interfaces (Speech Front-End \& On-Demand Vision)}
To support hands-free speech and camera queries at the counter, \texttt{Retail-AI-} integrates two auxiliary perception modules:
\begin{itemize}
    \item \textbf{Supporting Speech Front-End:} Combines local Silero VAD~v6, streaming Azure Speech with Thanh Lam Mart brand biasing (\code{PhraseListGrammar}), catalog-anchored brand repair, and SNR-adaptive denoising (client-side \texttt{GTCRN} WASM on serverless deployments or server-side \texttt{DPDFNet2} ONNX; details in Appendix~A.2).
    \item \textbf{On-Demand Mobile Visual Recognition (\texttt{MobileNetV3Large-224} TFLite + Sibling Pack-Size Guard):} Structured in three intuitive stages:
    \begin{enumerate}[leftmargin=1.5em, itemsep=1pt]
        \item \emph{Solving 1-image-per-SKU:} We fuse complementary embeddings from \texttt{CLIP-ViT-B/32} and \texttt{DINOv2-Small}~\cite{radford2021clip,oquab2024dinov2}, project via catalog-only SVD-256 (88.85\% variance retained), and distill into a 7.04\,MB \texttt{MobileNetV3Large-224} student~\cite{howard2019mobilenetv3,retail_tflite_kaggle} (plus 1.58\,MB gallery for 3,093 SKUs) under heavy 3D perspective/glare augmentation~\cite{deng2020subcenter,khosla2020supcon}.
        \item \emph{Local Fast-Path (23--27\,ms):} On an uploaded photo, if similarity is high ($\text{sim}_1 \ge 0.82$, margin $m \ge 0.08$) and no same-brand pack-size sibling exists (or $\text{sim}_1 \ge 0.92$), the local model returns the grounded SKU card immediately without cloud calls.
        \item \emph{Sibling Pack-Size Guard (Hybrid VLM):} Identical-layout pack sizes (e.g., 500\,ml vs.\ 900\,ml bottles) or non-retail images (OOD) escalate to a Hybrid VLM seeded with top-4 local candidates to read net weight accurately and reject OOD inputs.
    \end{enumerate}
\end{itemize}

\section{Contribution 2: Profit-Gated Router (\texttt{B-Gate}) and HITL Operations (\texttt{ops\_chest})}

In perishable replenishment, passing a wide raw quantile spread $(q_{90}-q_{10})$ directly into Newsvendor (Eq.~\ref{eq:order_qty}) can yield overly conservative safety stocks on volatile or sparse store segments.

Algorithm~\ref{alg:ops_chest_newsvendor} balances predictive accuracy and profit stability through our \textbf{Profit-Gated Router (\texttt{B-Gate})} in four steps: (1)~keep LightGBM's accurate median ($\hat{q}_{50}$) while pairing it with EWMA's smooth dispersion ($\sigma_{\text{EWMA}}$); (2)~enable ML only on store--SKU segments that prove positive out-of-sample profit lift (Eq.~\ref{eq:profit_gate}); (3)~compute FEFO-capped Newsvendor orders and graduated near-expiry markdowns; and (4)~hold every draft proposal in \texttt{PENDING} state until the Store Manager explicitly approves it.

\intuitionbox{One-Day Operational Walkthrough: How \texttt{ops\_chest} Coordinates with \emph{Mai}}{%
At 07:00 in Store~18, \texttt{ops\_chest} flags fresh SKU \code{F0005} (mapped to \code{TLM_10283202}, list price 123,900\,VND) with one day of shelf life left and excess stock. \textbf{Step 1:} \texttt{ops\_chest} creates a 25\% markdown draft in \texttt{PENDING} state; shoppers at the kiosk still see 123,900\,VND (strict HITL isolation). \textbf{Step 2:} The Store Manager approves the proposal (\texttt{EXECUTED}). \textbf{Step 3:} The read-only bridge immediately pushes the approved 92,925\,VND FEFO price to Mai so shoppers see the deal; once stock hits zero (\code{on_hand=0}), Mai automatically hides it from in-stock recommendations.}

\begin{algorithm}[htbp]
\caption{Profit-Gated Perishable Newsvendor (\texttt{B-Gate}), FEFO Caps \& HITL (\texttt{ops\_chest})}
\label{alg:ops_chest_newsvendor}
\footnotesize
\begin{algorithmic}[1]
\Require Store $s$ ($N_s$ SKUs), SKU $i$ with lot ledger $\mathcal{L}_i$, price $p$, cost $c$, salvage $v$, OOS cost $s_{\text{out}}$, shelf life $L$, review period $R$, capacity $C_{\text{room}}$, out-of-sample profit gate $V(g)$
\Ensure Verified proposal $P$ in \texttt{PENDING} state (zero direct execution)
\State Recover historical demand $\hat{D}_{i,t}$ via empirical hourly profile (Eq.~\ref{eq:wape_recovery}) and construct 29 tabular features
\State Compute EWMA $(\hat{\mu}_{\text{EWMA}}, \sigma_{\text{EWMA}})$ and LightGBM~v3 quantiles $(\hat{q}_{10}, \hat{q}_{50}, \hat{q}_{90})$
\State Assign segment $g = (\text{sales\_tier}(i), \text{intermittency}(i), \mathbb{I}[N_s > 30])$
\If{$V(g) > 0$ (Eq.~\ref{eq:profit_gate}) \textbf{and} $g$ is ML-enabled by the out-of-sample profit gate}
    \State Set expected demand $\hat{\mu} \gets \hat{q}_{50}^{\text{LGBM}}$ and dispersion $\sigma_{\text{daily}} \gets \sigma_{\text{EWMA}}$ (\code{ewma_sigma} variant)
\Else
    \State Set $(\hat{\mu}, \sigma_{\text{daily}}) \gets (\hat{\mu}_{\text{EWMA}}, \sigma_{\text{EWMA}})$
\EndIf
\State Compute $SL^*$ and $z = \Phi^{-1}(SL^*)$ (Eq.~\ref{eq:newsvendor}) with floors 0.95 (traffic), 0.90 (ABC-A), 0.50 (other)
\State Evaluate FEFO lot depletion over review period $R$ and window $W = \min(90, L)$ to obtain $U_R$, $L_R$, and $S_W$
\State Compute shelf-life-capped order $Q^* = \max(0, \min(Q_{\text{raw}}, Q_{\text{cap}}, C_{\text{room}}))$ (Eq.~\ref{eq:order_qty})
\State Flag lots expiring within $\le 2$ days exceeding full-price demand for graduated FEFO markdown proposals
\State Persist draft $P$ as \texttt{PENDING} via 9 proposal tools; inspect explanation via \code{guard.py}
\State Transition to \texttt{EXECUTED} and expose via \code{ops_bridge} \textbf{only} after authenticated manager approval
\end{algorithmic}
\end{algorithm}
